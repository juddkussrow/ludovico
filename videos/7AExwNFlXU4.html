Running a 22GB AI Model on a 6GB GPU, FAST (llama.cpp Guide)

This video demonstrates how to run the Qwen3.6-35B-A3B Mixture of Experts (MoE) model, a 22GB AI model, on a 6GB GPU using `llama.cpp`. It details five critical flags and optimizations, including `--n-cpu-moe` for offloading experts to system RAM and tuning `load-mode` (mmap vs mlock), to achieve 17 tokens per second on older hardware like a GTX 1060. The tutorial also covers memory traffic mechanics for sparse models, KV cache optimization with TurboQuant, and micro-batch tuning for prompt processing.

The Qwen3.6-35B-A3B model, released by Alibaba on April 15th, 2026, is a 35 billion parameter model where 3 billion parameters fire per token, making it sparse. The 4-bit build from Unsloth is 22.36 GB. The core optimization involves leveraging `llama.cpp` flags to offload idle expert weights to system RAM. The first key flag is `--n-cpu-moe N`, which keeps the expert weights of the first N layers on the CPU. Setting `--n-cpu-moe 30` on a GTX 1060 increases performance from 3 t/s to 10 t/s. The optimal `N` is found by starting with all layers on CPU and decrementing until VRAM runs out, then stepping back one. Tools like Ollama and LM Studio lack granular control over this, with Ollama automatically splitting models and LM Studio offering only an all-or-nothing checkbox. The second flag, `--no-mmap` (now part of `load-mode`), can boost performance from 10 t/s to 13.5 t/s by loading the entire model into RAM upfront, though `mmap` can be faster if the model exceeds system RAM. The third flag is `n_gpu_layers`, which pushes layers back to the GPU until VRAM fills up, increasing performance to 17 t/s. The fourth flag, `mlock`, prevents the kernel from paging out expert pages over long sessions. The video highlights that once experts are in system RAM, performance becomes memory bandwidth-bound (e.g., 51 GB/s for DDR4 vs 192 GB/s for GTX 1060 VRAM). Prompt processing is optimized by micro-batch tuning, specifically by adjusting `op_offload_min_batch_size` in the CUDA backend, which defaults to 32. For single-token generation (batch size 1), the CPU handles the work, but for multi-token prompts (batch size > 32), `llama.cpp` copies experts to VRAM for GPU processing. A patch in August 2025 (PR #15346) improved this by copying only used experts. Context handling is addressed by TurboQuant (Google Research, NYU), which uses 3-bit quantization for the KV cache, reducing its size significantly (from 5GB to 1.09GB for 256k tokens). However, TurboQuant is not merged into upstream `llama.cpp` and requires a forked build. Speculative decoding is shown to fail on MoE models because it wakes too many experts, increasing data movement across the memory bus and slowing down verification. Multi-token prediction (MTP) offers a partial workaround, providing 1.15x-1.25x speedup on MoE models compared to 1.4x-2x on dense models. The video concludes that 4-bit quantization quality is sufficient for practical use, despite some drift, and that VRAM is no longer a "wall" but a "budget" for sparse models.
