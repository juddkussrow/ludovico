Traditional coding agents waste tokens by repeatedly searching for relevant files using terminal commands, sending the entire conversation history and tool results with each turn, leading to context window bloat, slower model performance, and increased costs. Graft solves this by building a knowledge graph of the project, mapping every part of the code and its connections. This graph is saved as a JSON file and can be viewed in a browser. Unlike vector search, which relies on similarity and can lead to incorrect matches (e.g., "create an account" vs. "delete an account"), Graft understands actual code relationships. Graft integrates with Claude Code by creating a skill that instructs the agent on how to use the knowledge graph. It also installs hooks: one to provide instructions at session start, one to attach up to three matching locations to every prompt, and one to update the map after Claude edits a file. For existing projects, `graft build` maps the current codebase. Users can install Graft via a command or by pasting a setup prompt into their agent. The `graft init` command, run within the project folder, sets up Graft for the specific coding agent (Claude Code or Codex). Graft offers both a CLI version and an MCP (Message Control Protocol) option; MCP resulted in slightly more correct answers, while CLI was faster. Graft claims significant improvements: 60% less time, 46% fewer tool calls, 42% fewer tokens, and 32% lower cost on average across 162 runs. In a real-world test, building a booking app with Fable 5.1, the Graft-assisted build took 39 minutes and used 31% of the context window, compared to 47 minutes and 35% without Graft. The benefits become more pronounced on larger projects and subsequent changes, as Graft leverages its pre-built map. Graft only maps code files, not other project documents like PRDs or notes, meaning agents revert to default search methods for these non-code files.
