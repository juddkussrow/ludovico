The core technology is fountain coding, which generates an unlimited stream of encoded frames, each a mathematical blend of file pieces, making the transfer resilient to missed frames. The theoretical throughput ceiling for Decimen is calculated at 177 KB/s, with the readme claiming 128 KB/s due to fountain coding overhead. This is based on sending 2,953 bytes per frame (QR code version 40) at 60 frames per second. A real-world test from a laptop to a phone achieved only 3 KB/s, with only 1-2% of frames decoded. This low performance is attributed to three main issues: frame rate mismatch (sender at 60 FPS, phone camera at 30 FPS, leading to blended frames), code density versus camera resolution (QR version 40 requires high resolution and sharp focus, which a laptop screen at arm's length doesn't provide), and brightness/contrast. The video highlights that the Decimen defaults are tuned for close-range phone-to-phone transfers. A phone-to-phone transfer, where the sender is a bright OLED screen filling the receiver's frame, achieved 41.1 KB/s, closer to the claimed performance. The tool's diagnostics show separate capture FPS and decode FPS, indicating when the camera can't resolve the dense frames. To fix laptop-to-phone transfers, the recommended adjustments are to reduce bytes per frame to 1,465 (a coarser QR version) and transmit FPS to 24, deliberately below the camera's 30 FPS ceiling, yielding significantly improved throughput. The creator concludes that optical file transfer requires manual tweaking for different hardware setups.
