Astryx aims to solve the trade-off between adopting a rigid big-company system like Material UI (which limits customizability) and using copy-paste component collections like Shadcn (which leads to maintenance overhead and lack of shared coherence). Astryx controls behavior, accessibility, and quality, while themes control appearance through token-level customization (color, type, radius, motion) without rewriting components. The presenter demonstrates creating a custom theme using `defineTheme` function, showing how a single accent color can generate a full color palette. Typography options include base size and ratio for scaling text sizes. Radius controls corner sharpness, and motion controls animation speed. The system supports type-safe token overrides for fine-grained control, allowing changes to specific tokens (e.g., `--color-neutral` for secondary button background) or component-specific styling (e.g., changing text color for a secondary button variant without affecting global text). Custom variants can also be defined. Astryx supports pre-built themes and theme extension, and themes can be built for production, generating static CSS and JavaScript for server-side rendered apps like Next.js. A key benefit is enforcing brand consistency, contrasting with Tailwind where developers might introduce style drift. While Tailwind can achieve similar tokenization, it lacks type safety. Direct component styling is possible using `xstyle` (StyleX-based), other libraries like Tailwind or Panda, or plain CSS. Astryx also features a "Tailwind bridge" that maps Astryx design tokens to Tailwind utility classes, though the presenter prefers StyleX. A significant feature is Astryx's integration with AI agents, offering an Astryx CLI for agents to fetch documentation, load context, and fill `agents.md` files. Models like Fable and GPT were found to work well with Astryx.
