WebMCP aims to solve the problem of AI agents "squinting at pixels" by allowing websites to "publish tools, not pixels." Currently, AI agents browse the web using brittle methods like mouse automation, DOM scraping, or screenshots, which are expensive (2,000 tokens per screenshot) and prone to breaking with minor UI changes. WebMCP transforms a web page into a "tool server" within the browser tab, enabling agents to call structured tools directly. This reduces token cost to around 50 tokens per call and increases task accuracy to 98%. The process involves four steps: register (page declares tools via `navigator.modelContext`), discover (agent asks browser for available tools), invoke (agent calls tools with typed parameters), and respond (tool returns structured data or errors). Tools are defined by a name, description, input schema, and an execute function. WebMCP offers two APIs: a declarative API using HTML forms with `toolname` and `tooldescription` attributes (no JavaScript needed), and an imperative API using JavaScript's `registerTool` for dynamic tools. The system ensures user control with same-origin restrictions and user confirmation for sensitive actions. This approach is faster, cheaper, more reliable, and provides a consistent interface for both AI agents and assistive technologies like screen readers. Google's early previews highlight use cases in customer support, e-commerce, and travel. The video predicts that by 2027, being "agent-ready" will be "table stakes" for websites.
