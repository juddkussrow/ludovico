The creator, Matt Pocock, explains that traditional AI planning tools often feel too constrained, leading to developers limiting their ambitions to fit AI capabilities. Wayfinder addresses this by allowing users to map out "foggy ideas" into concrete execution plans, managing research, prototyping, and task management. It operates by creating a "map" of tickets within an issue tracker (demonstrated using GitHub), where each ticket represents a decision or task. These tickets can be of four types: research (for information gathering), prototype (for creating high-fidelity mockups), grilling (for discussions on implementation details), and tasks (for real-world actions). Wayfinder establishes blocking relationships between tickets, ensuring decisions are made in the correct order. The tool tracks the "frontier" of actionable tickets and the "fog of war" for undecided items. Once a map is complete, Wayfinder can generate a detailed specification document, which can then be used to create individual implementation tickets. This process is contrasted with the "grill with docs" approach, where Wayfinder provides a more detailed, primary source of truth for decisions. The creator emphasizes that Wayfinder is for projects with a "fog of war" where the destination is unclear, not for straightforward tasks. It is issue tracker agnostic, compatible with tools like Linear and Jira, and has been used for both coding and non-coding tasks (e.g., planning a garden office). The specs generated by Wayfinder are considered non-persistent, serving as a destination document for multi-session work rather than a living document to be continuously edited.
