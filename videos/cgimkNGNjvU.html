He outlines Snyk's three-pillar approach: securing what agents generate, use, and do. Initially, Snyk used an MCP server with rules to secure generated code, but this proved limited as agents often ignored rules, and scans added latency and token consumption. The new approach uses asynchronous Python hooks that trigger scans via Snyk's CLI on file writes, surfacing only newly introduced issues to the agent context, making the workflow deterministic and efficient. For the "what agents use" pillar, Snyk, after acquiring Invariant Labs, developed a solution to auto-discover and analyze agent components (MCP servers, skills, CLIs, models) on a machine, assigning risk scores. An audit of nearly 4,000 skills on Claw Hub revealed over 1 in 8 had critical severity issues and 76 carried malicious payloads, highlighting skills as more dangerous than package dependencies due to higher privilege and memory modification capabilities. The "what agents do" pillar focuses on governing agent behavior through policy configurations to prevent exfiltrative, destructive, or malicious actions. The demo showcases "Snappy," a local Electron app that acts as a security pair programmer. Snappy monitors files, runs background scans, and automatically fixes vulnerabilities by launching coding agents. It provides local visibility into running LLMs, AI components (MCP servers, skills, CLIs, models) with risk scores. Users can set project-specific guardrails. In a live demonstration, Snappy successfully blocked Claude from reading an `ENV` file and a secret key, illustrating its ability to enforce policies and prevent sensitive data access.
