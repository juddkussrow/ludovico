It is presented as a "tmux for the AI agent era," running inside the user's existing terminal. Herdr's core functionality is its ability to understand and track the live state of AI agents (working, blocked, idle, done) across multiple panes, tabs, and spaces, which tmux cannot do as it only sees processes. It features a sidebar that displays the state of all detected agents, eliminating the need to manually check each pane. Herdr supports around 20 agent CLIs out-of-the-box, including Claude Code, Codex, Open Code, Gemini CLI, Cursor Agent, Copilot CLI, Gro CLI, Quen Code, Kilo Code, Droid AMP, and Devonro. For agents without direct life cycle hooks (like Claude Code), Herdr uses screen matching heuristics to detect states. Installation is via `brew install herdr` on Mac, a curl script for Linux (`curl -fsSL herdr.dev/install.sh | sh - linux`), or `cargo install herdr` for Rust users. It maintains existing terminal fonts, colors, and shell configurations. The interface uses `Ctrl+B` as a prefix key, similar to tmux, but also supports mouse interactions for pane management. A key feature is its automation layer, providing a CLI and local socket API that agents can use to orchestrate each other, such as splitting panes, starting other agents, sending prompts, waiting for results, and reading output. This enables complex multi-agent workflows where agents can coordinate tasks. Herdr also offers persistence, with a client-server model that allows sessions to survive disconnects and server restarts, including native agent session restoration for supported agents. It has a remote mode (`herdr --remote`) to run agents on a dev server or VPS while controlling them locally. Configuration is done via `~/.config/herdr/config.toml` and supports themes like catppuccin, gruvbox, nord, and dracula, with live reloading. It also has a plugin system. The creator compares Herdr to Verdant, stating that Verdant handles larger, well-defined project work with built-in planning and delegation, while Herdr manages faster, terminal-native ad-hoc tasks.
