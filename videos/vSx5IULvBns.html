He highlights that 70% of an engineer's time is spent running, not writing, software, a problem exacerbated by AI-generated code increasing the volume of changes. Resolve AI offers an agent-based platform to address this by automating production operations. The platform features on-call agents for alert triage and root cause analysis, incident agents for larger cross-team issues, and background agents for continuous operational tasks. These agents operate based on three principles: when they run (schedule, event streams, or message-based), how they run (in a cloud sandbox with its own file system), and how they know what to do (tasks, skills, and integrations). Smith demonstrates four key workloads for background agents: deployment monitoring, scheduled health and anomaly checks, operational reports and handoffs, and acting as a first responder to engineering questions. For deployment monitoring, an agent detects a GitHub release tag in Slack, analyzes the code changes, and dynamically creates a customized check plan. For example, if a checkout service replaces a currency service, the agent monitors checkout latency, error rates, and the Kafka pipeline. This monitoring is not hardcoded; the agent can decide to re-check in an hour or three days based on the nature of potential failures. The agent can also generate daily operational reports, summarizing investigations and notable changes. A unique feature is a Slack-watching agent that can answer engineering questions with confidence, or DM a human engineer for confirmation before replying publicly. The core idea is that execution is easy, but understanding "production context" (e.g., knowing when a metric "smells wrong") is crucial, and Resolve AI aims to build the knowledge system for this context.
