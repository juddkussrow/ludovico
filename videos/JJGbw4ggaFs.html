The core idea is to continuously analyze production context (traces, queries, latency) to identify performance anti-patterns, score high-ROI opportunities, and generate verified fixes. The system uses GitHub Actions for weekly runs, with Cloud Code as a specific choice for compute, and captures runtime intelligence via MCP to connect endpoints to function-level overhead. The agent analyzes issues like N+1 queries and missing database indexes, then reruns tests to verify the fix's impact. The output is a human-friendly report detailing the problem, its business impact, and a proposed fix, allowing engineers to create a ticket or PR. Challenges encountered include "plausible, unverified" fixes from agents, complex queries (especially with ClickHouse), and agents suggesting "lazy fixes" instead of root cause solutions. Hud's "prod-to-code" approach provides function-level context to agents, bridging the gap between service-level metrics and code. The system is built on a "Runtime Intelligence MCP" pyramid: HudQL (ClickHouse queries) at the base, Skills (e.g., for HTTP 500s, memory spikes) on top, and Automations (auto-fix, dead code detection, performance improvements) at the apex. The scoring mechanism prioritizes fixes based on "hot path," "business impact," and "risk," aiming for high-ROI opportunities. The goal is to automate the investigation phase, providing actionable insights before sprint planning, and ensuring high confidence in the suggested fixes before human review.
