The core structure of a loop involves a markdown file containing a "loop contract" (goal, boundary, SOP), state, and logs. The "loop contract" defines the winning condition, what the agent can do autonomously versus what requires human escalation, and specific workflows. The "state" is a durable snapshot of the agent's current hypothesis, backlogs, and shipped items needing follow-up, while "logs" are an append-only record of past runs to prevent redundant work. Triggers for these loops can be continuous (like a `while` loop until a goal is met, good for immediate feedback tasks like bug fixing, using `/goal` command), time-based (cron jobs, using `/loop` or `/schedule` commands, supported by Cloud Code/CodeX), event-based (reactive to events like new emails or server incidents, not natively supported by Cloud Code/CodeX, requiring a local demon process and webhooks), or workflow-based (running a script to check for new work before waking the agent, e.g., fetching Intercom updates). The agent itself typically goes through stages: gathering signals, prioritizing work, executing, and verifying. For complex tasks, an orchestrator agent spawns executor sub-agents in isolated worktrees, which then hand off to verifiers that test results and attach evidence (e.g., using Playwright for video/image evidence, Crabbox for sandbox environments). The `verifier-setup` skill is provided for this. A crucial aspect is the "evolve loop," where the agent itself optimizes its configuration, contract, and scripts based on past runs and logs. The creator demonstrates Loopany, an open-source tool that provides a dashboard to manage these loops, track PRs, health scores (e.g., for the "React Doctor" loop), and facilitates the evolution process. Loopany stores loop contracts, state, logs, and triggers, and includes built-in evolve loop behavior. It offers templates for common loops like a "doc maintainer" that checks for documentation drift and opens PRs for fixes, and a "React Doctor" that fixes critical code issues daily.
