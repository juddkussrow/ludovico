Don't Ship Skills Without Evals — Philipp Schmid, Google DeepMind

@octopusinc_ · 2026-07-14 · DevOps

This video emphasizes the critical need for evaluation (evals) when developing and deploying AI agent skills, particularly for customer-facing applications. It outlines a methodology for building reliable agent skills, including best practices for writing effective skill descriptions, structuring skill files, and implementing a lightweight eval harness using regex and LLM-as-a-judge techniques. The core message is that rigorous testing prevents failures and ensures skill efficacy, similar to how code is tested before deployment.

A skill is defined as a versionable folder with a `SKILL.md` file and supporting assets, operating on progressive disclosure (Layer 1: Frontmatter, Layer 2: SKILL.md Body, Layer 3: References & Scripts). Skills are categorized into "Capability Skills" (temporary, teaching models new abilities) and "Preference Skills" (durable, encoding team workflows). Skill Bench 1.1 shows skills improve performance by ~15%, but AI-generated skills can negatively impact performance. Human-written skills are preferred, and `SKILL.md` files should be under 500 lines. Skills can be model-invoked (autonomous) or user-invoked (slash command). For model-invoked skills, the description is crucial; vague descriptions cause 50% of failures. Skills should be lean, layering information to save tokens, with frontmatter always loaded, skill body on trigger, and references on demand. Skills should define goals and constraints, not rigid step-by-step procedures, which are better suited for scripts. Negative test cases are important to prevent "hijacking" by unrelated prompts. "No-ops" (instructions that don't alter agent behavior) should be removed to save tokens. Skills should be retired when models improve enough to absorb their functionality. A case study on the Gemini Interactions API Skill demonstrates improving model performance from 28.2% to 96.4% for Gemini 3.1 Pro, 6.8% to 93.2% for Gemini 3.0 Pro, and 8.7% to 89.7% for Gemini 3.0 Flash using 117 test cases. Evals can use fast regex checks for SDK imports, model usage, and deprecated patterns, or LLM-as-a-judge for complex skills. Google DeepMind uses YAML configs for evals, running them in isolated workspaces with CLI checks and LLM judge criteria, requiring proof of positive skill lift before merging changes.
