This video introduces SecretSpec, a CLI and SDK tool written in Rust, designed to manage application secrets declaratively. It aims to improve upon traditional .env files by decoupling secret values from the codebase, storing them securely in various providers like system keyrings or password managers, and making secret management more robust and discoverable. SecretSpec allows defining secrets in a `secretspec.toml` file, setting values via the CLI, and running applications with secrets injected as environment variables or accessed directly through SDKs.

The core problem addressed is that .env files make projects not fully self-contained, hide secret names from new contributors, and do little to prevent leaks. SecretSpec solves this by decoupling secret values from the codebase, allowing them to be stored in secure, encrypted locations like system keyrings (macOS Keychain, Windows Credential Manager, Linux Secret Service) or services such as Bitwarden, LastPass, 1Password, AWS Secrets Manager, HashiCorp Vault, OpenBao, Proton Pass, and Google Cloud Secret Manager. Users define secrets by name in a `secretspec.toml` file, which can include descriptions, default values, and specify if a secret is required. The `secretspec set` command is used to input secret values, which are then stored by the chosen provider. The `secretspec get` command retrieves these values. Applications can be run with secrets injected as environment variables using `secretspec run -- <command>`. SecretSpec also offers SDKs for various languages (Python, Ruby, Go, Node, Haskell, Rust) to resolve secrets directly from code, bypassing environment variables. For Rust, a macro enables compile-time, type-safe secret access. Key features include guardrails that prevent projects from running if required secrets are not set and prevent setting undefined secrets. It supports profiles, allowing different rules for various environments (e.g., a required API key in default profile, but a default testing value in a development profile). SecretSpec also provides secret generation capabilities, audit logging, and integration with development environments like NYX. The `secretspec config init` command allows users to set a default provider and profile, storing these preferences in a user config file. The tool is presented as a superior alternative to .env files, enhancing security, discoverability, and management of secrets across different environments and providers.
