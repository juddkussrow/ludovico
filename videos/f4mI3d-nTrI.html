Previously, MCP required an `initialize` handshake and an `Mcp-Session-Id` header, pinning clients to specific server instances and causing issues with load balancing (e.g., 400 session not found errors if routed to a different instance or if an instance crashed). Workarounds like sticky sessions or a shared Redis instance added complexity and latency. The new spec, specifically SEP 2575 and SEP 2567, removes the `initialize` handshake and the `Mcp-Session-Id` header, making every request independent. This enables standard round-robin load balancing, eliminates the need for Redis for session management, and allows servers to scale to zero on platforms like Cloudflare Workers or Google Cloud Run. The update also introduces new HTTP headers, `Mcp-Method` and `Mcp-Name`, allowing gateways to make decisions without parsing JSON, and adds `ttlMs` and `cacheScope` caching hints, similar to HTTP caching. Handshake information is now carried in a `_meta` field within the JSON body of each request. For managing state, the protocol now defers to standard HTTP API practices, allowing tools to mint explicit handles. Multi Round-Trip Requests (MRTR) replace the old open-stream elicitation, where the server returns an `input_required` result with a `requestState` payload, and the client reissues the call with user input. Long-running tasks, previously experimental, are now an official extension, allowing tools to return a task handle and clients to poll for progress or subscribe to results. The update involves breaking changes, but deprecated features will have at least 12 months before removal. TypeScript SDKs are now split into `@modelcontextprotocol/server` and `@modelcontextprotocol/client` packages, and a codemod (`npx @modelcontextprotocol/codemod@beta v1-to-v2`) is available for API renames.
