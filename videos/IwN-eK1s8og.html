It's built on Andrej Karpathy's LLM Wiki concept and Google's Open Knowledge Format (OKF) spec, storing memories as plain markdown files. The system avoids vector databases and cloud APIs, running entirely on the user's local machine, including the harness, memory, and model (using the same llama.cpp server as other tools). The core architecture involves a "librarian" agent that manages the memory, which is organized with `index.md` files and links between concepts. The system is deterministic, using LLMs only for decisions. The UI for understory includes a chat interface, a memory graph visualizer (using d3-force), and query path replays for debugging. It integrates with other AI systems like AnythingLLM and llama.cpp web UI via the MCP protocol, offering `Query`, `Update memory`, and `Add memory` tools. The creator highlights two main challenges encountered during development: the "cold-start problem" and the "junk-drawer problem." Initially, client models wouldn't consult the memory because they only saw tool names and had no reason to look. The fix involved providing a "seed memory" – a live summary of the knowledge base – to the client model at startup via MCP instructions and query tool descriptions. This summary lists concepts (e.g., "billing," "people") rather than filenames. The "junk-drawer problem" arose when the AI created new, disconnected files for every new fact. This was solved by implementing two rules for the librarian agent: "enrich before you create" (patching new facts into existing concepts) and "link both ways" (creating new concepts but linking them to related existing ones). The creator notes that Gemma 12B struggled with the agentic decisions for organizing memory, while Qwen 3.6 35B performed well on a single consumer GPU. Further refinements include a lint step for graph health (identifying orphans and broken links, excluding auto-generated index files), a maintain tool to wire orphans back into the graph, and a rule to prevent contradictions by rewriting facts instead of appending. The entire stack uses TypeScript, Vercel AI SDK v5, Node, Express, React, Vite, and Tailwind, with Docker for deployment.
