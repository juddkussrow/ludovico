This video introduces FreeToken, an open-source inference engine designed to run Mixture-of-Experts (MoE) AI models faster than Ollama, especially when models exceed GPU VRAM capacity. FreeToken achieves this through expert caching, double buffering, a Q* policy for CPU/GPU split based on bandwidth, and a custom FTW weight format. The video demonstrates FreeToken's performance against Ollama on an RTX 5090, highlighting its advantage when models overflow VRAM and its limitations when models fit comfortably.

It addresses the challenge of MoE models, where only a small subset of parameters (e.g., 13 billion out of 284 billion for DeepSeek-V4-Flash) are active per token, but the entire model must reside in RAM. FreeToken's core innovation is treating GPU memory as a cache for frequently used experts, with the full model in system RAM. It employs double buffering during prefill to stream next layers while the GPU computes the current one, and a "Q* policy" during generation to dynamically split missing expert computations between GPU (via PCIE transfer) and CPU, based on real-time bandwidth measurements. This adaptive approach optimizes for specific hardware configurations (e.g., laptop vs. desktop). FreeToken also uses a custom FTW weight format to skip repackaging, speeding up model loading. A demo on an RTX 5090 with 32GB VRAM and 64GB DDR5 RAM compares FreeToken and Ollama using a Qwen 3.6 35B model (38GB, 6GB over VRAM capacity). Ollama splits the model by layer, placing 70% on GPU and 30% on CPU, resulting in 58 tokens/second. FreeToken keeps computation on GPU, streaming missing experts, achieving 132 tokens/second for the same task. FreeToken also allows live resizing of its GPU expert cache, demonstrating that a small cache (e.g., 10% of the model) can maintain high speed, but shrinking too much (below 20%) causes performance to drop due to PCIE saturation. However, FreeToken is not a universal solution; for a 4-bit Qwen 3.6 model that fits entirely within VRAM, Ollama (240 tokens/second) outperforms FreeToken (225 tokens/second) because FreeToken's streaming architecture introduces overhead when not needed.
